# Sol.trusted_identity 0.4.1

MaiBot QQ 回复目标身份核验与群聊特别关注插件。只根据可信来源的当前目标元数据核验，不按昵称、自称或聊天正文判断。**专属称呼由使用者填写，默认留空**。

## 配置

本仓库和安装包不附带 `config.toml`；首次加载时，宿主根据插件的 `config_model = Config` 配置模型生成默认配置。默认关闭、账号与称呼为空；请在插件管理页填写。

安装后默认关闭。先填写绑定账号 QQ、机器人 QQ，阅读并确认 SnowLuma 原生 QQ 单发送者消息来源，再启用插件。绑定账号称呼 `qq_binding.creator_name` 可留空，也可填写自己希望使用的称呼（最多32字、单行）。空称呼只报告核验事实，不向模型提供专属称呼；不会自动继承旧称呼。模型可能仍受自己的角色设定影响，本插件不修改宿主人格或历史记录。

在“群聊特别关注 → 关注账号与称呼”中，可新增、删除条目，并逐人编辑 QQ 和称呼。关注不代表好友、亲密关系或额外权限。称呼只在本次群聊回复目标核验命中后传给模型；QQ 仅在本机比较。

下面均为合成示例：

```toml
[qq_binding]
creator_qq = "800000001"
bot_qq = "900000001"
creator_name = "" # 可自行填写称呼
confirmed = false # 阅读来源确认后自行修改

[attention]
enabled = true

[[attention.users]]
qq = "800000002"
name = "小星"

[[attention.users]]
qq = "800000003"
name = "" # 留空仍可匹配关注，但不指定称呼
```

已有 `attention.qq_numbers` 会自动迁移成“QQ＋空称呼”的条目，不会删除旧名单。若同时存在新旧列表，显式 `users` 优先，包括用户主动清空的新列表。同一 QQ 不允许重复；若绑定账号也在关注列表中，两项核验各自报告，绑定账号称呼优先参考。

配置更改会清空内存缓存；用更改后新收到的消息验证。Planner 只收身份使用规则，不预判当前目标；Replyer 收本次核验事实。未核实不等于冒充，模型是否采用称呼仍取决于模型行为。称呼是数据，不能授予任何管理员、系统或工具权限。

## 安装

在 MaiBot 插件管理页上传单插件 ZIP，按宿主提示重启。也可把 ZIP 内整个插件目录解压到 MaiBot 的插件目录，避免多套目录。已安装同 ID 插件时，上传接口拒绝覆盖；升级前备份现有插件和配置，并按宿主支持的方法更新。**升级时保留自己的本地配置；不要把本机生成的配置上传到仓库。**

验证环境：MaiBot Host **1.3.19** / SDK **2.21.0**。其他版本未验证。使用宿主自带 Python、Pydantic 与 maibot_sdk，无须额外安装 pip 包。两个 Sol 插件互不依赖，不依赖分段插件。非 QQ、不同适配器、自定义 scope 或混合来源尚未适配，安装成功不等于来源语义已验证。

开发自检：在插件目录使用 MaiBot Python 运行 `python -m unittest discover -s tests -p "test_*.py"`。

## 隐私、来源与限制

配置模型的默认值不含账号绑定、关注名单或私人称呼。源码包不包含本机路径、API 配置、日志、聊天快照、配置历史或备份；测试使用合成数据。称呼在核验命中后会随请求发送给所用模型服务，请按自己的数据使用要求填写。
